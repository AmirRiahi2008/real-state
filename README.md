# ORIVA — UAE Real Estate

وب‌سایت املاک **ORIVA** با **Next.js 16 و NestJS 12**، PostgreSQL، Prisma و Redis. صفحهٔ اصلی بازنمایی سه‌بعدی برج خلیفه را با Three.js می‌سازد. GSAP روایت وابسته به اسکرول و Motion حرکت‌های رابط را اجرا می‌کنند؛ نوار رنگی بالای صفحه با پیشرفت اسکرول پر می‌شود.

لندینگ یک صحنهٔ تمام‌صفحه با ۱۲ فصل و مسیر اسکرول حدود ۲۱٬۰۰۰ تا ۲۹٬۰۰۰ پیکسل است؛ برای روایتی نزدیک یک دقیقه با اسکرول معمولی طراحی شده و مدت واقعی به سرعت کاربر بستگی دارد. مدل شامل پلان سه‌شاخه و هستهٔ مرکزی، ۱۶۳ طبقه، عقب‌نشینی‌های متوالی، نمای شیشه‌ای با تیغه‌های فلزی، تاج و نوک برج است. گودبرداری، شمع‌ها و آرماتور، قالب متحرک، جرثقیل بالارونده، ۱۶ کارگر مفصل‌دار، میکسر، کامیون، پمپ و حفّار با یک مقیاس مشترک ساخته شده‌اند. دوربین بین نمای نزدیک افراد و ماشین‌آلات و نمای کامل برج حرکت می‌کند. روایت با اسکرول معکوس بازمی‌گردد؛ در حالت کاهش حرکت دستگاه، نمای تکمیل‌شده و متن فصل‌ها بدون مسیر طولانی نمایش داده می‌شوند. ابعاد نمایشی و مقطع‌ها یک بازنمایی معماری‌اند و نقشهٔ اجرایی بنا نیستند. مرجع طراحی: [وب‌سایت رسمی برج خلیفه](https://www.burjkhalifa.ae/the-tower/architecture-design/).

صحنهٔ شهری پیرامون برج، با الهام از بافت Downtown دبی، ۱۳۹ ساختمان با فرم‌های متنوع، خیابان، خودرو و روشنایی شب دارد و بازسازی GIS دقیق نیست. نما و نور پنجره‌ها به‌صورت بافت‌های محلی ساخته می‌شوند؛ هندسهٔ شهر بر اساس متریال ادغام شده است. دوربین در نماهای دور عمق برش را تطبیق می‌دهد تا سطح آب و محوطه با زمین تداخل نداشته باشند. ظاهر عمومی سایت با پالت روشن و تاریک، پرچم کوچک امارات کنار لوگو و نمای معماری تازهٔ بالای QA هماهنگ شده است.

نور شب با شدت ملایم و اتاق‌های روشنِ خوشه‌ای ساخته می‌شود؛ بافت نمای شهر فیلتر خطی و mipmap دارد و لبهٔ نور پنجره‌های برج نرم می‌شود. تغییر آرام و مستقل روشنایی اتاق‌ها در شیدر اجرا می‌شود؛ در حالت کاهش حرکت، نور ثابت است.

چراغ‌های بیرونی برج با نور سفید نقره‌ای، هالهٔ نرم و درخشش چهارپر به لبهٔ نما، تراس‌ها، تاج و نوک برج متصل‌اند؛ نوارهای روشن عقب‌نشینی‌ها را مشخص می‌کنند. چراغ‌ها با نصب همان بخش از نما ظاهر می‌شوند و در اسکرول معکوس جمع می‌شوند؛ درخشش آرام در حالت کاهش حرکت ثابت است. مرجع بصری: [تصویر شب برج](https://www.amassmiddleeast.com/burj-khalifa.jpg) و [معرفی نورپردازی نما از Emaar](https://www.emaar.com/en/press-release-listing/burj-khalifas-facade-gets-a-dazzling-lighting-overhaul).

زبان پیش‌فرض انگلیسی و تم پیش‌فرض روشن است؛ عربی راست‌به‌چپ و تم تاریک هم پشتیبانی می‌شوند. صفحات جستجو و جزئیات ملک و پروژه، فرم استفسار و بازدید و محاسبه‌گر سرمایه‌گذاری به API واقعی وصل‌اند. پنل مدیریت مستقل در `/{locale}/admin` مدیریت محتوا و داده‌های سایت را در دسترس ادمین قرار می‌دهد.

صفحهٔ [QA در لوکال](http://localhost:3000/en/qa) اعضای تیم و گفتگوی خصوصی با هر نفر را نمایش می‌دهد؛ Melika در مرکز چیدمان سلسله‌مراتبی قرار دارد و کارت‌های Amir و Mehdi با مسیرهای متحرک به آن متصل‌اند. [ورود تیم](http://localhost:3000/en/dashboard/login) به پنلی محدود برای پروفایل، عکس، رمز و پیام‌های همان عضو می‌رسد؛ عنوان نمایشی، مجوز امنیتی حساب را تغییر نمی‌دهد و دسترسی ویرایش محتوای سایت وجود ندارد. راهنمای [پنل تیم و پیام‌ها](docs/team-workspace.md) روش ساخت حساب‌های محلی بدون ذخیرهٔ رمز در سورس را توضیح می‌دهد.

پنل [ورود ادمین در لوکال](http://localhost:3000/en/admin/login) شامل نمودارهای واقعی ۷/۳۰/۹۰ روزه، املاک، پروژه‌ها، مقالات، مناطق، توسعه‌دهندگان، امکانات، مشاوران، تصاویر، کاربران، تیم، درخواست‌ها، گفتگوها و سابقهٔ تغییرات است. ویرایش محتوای دوزبانهٔ سایت، متن فصل‌های ساختمان و FAQ با کنترل نسخه انجام می‌شود. راهنمای [پنل ادمین](docs/admin-workspace.md) حدود دسترسی و راه‌اندازی محلی حساب را توضیح می‌دهد.

اخبار و مقالات و توضیحات املاک و پروژه‌ها، ادیتور غنی Tiptap دارند: بولد و ایتالیک، تیتر و لیست، لینک، جدول، تصویر و زیرنویس، پیش‌نمایش و حالت تمام‌صفحه. متن‌های قبلی حفظ می‌شوند و محتوای قالب‌بندی‌شده به‌صورت ساختاریافته و با کنترل مستقل بک‌اند ذخیره می‌شود.

لودر آغازین با آماده‌شدن فونت‌ها و اولین فریم صحنه کنار می‌رود؛ صفحه‌های دیگر ورود انیمیشنی و حالت کاهش حرکت دارند.

قابلیت‌ها: ثبت‌نام و احراز هویت، تأیید ایمیل و بازیابی رمز، آگهی فروش و اجاره، پروژه‌های off-plan، مناطق و امکانات و توسعه‌دهندگان، پروفایل عمومی مشاوران، مدیریت انتشار، درخواست بازدید و مشاوره، علاقه‌مندی و جستجوی ذخیره‌شده، محتوای EN/AR، آپلود تصویر و محاسبه اقساط و بازده اجاره.

## اجرای محلی

پیش‌نیازها: **Node.js 24** با حداقل نسخه `24.11.0`، **npm 11+** و Docker Desktop با Docker Compose v2. فایل `.nvmrc` نسخه اصلی Node را مشخص می‌کند.

```bash
git clone https://github.com/AmirRiahi2008/real-state.git
cd real-state
nvm install
nvm use
npm ci
npm run setup:local
npm run infra:up
npm run db:generate
npm run db:deploy
SEED_DEMO=true npm run db:seed
npm run dev
```

اگر از nvm استفاده نمی‌کنید، Node 24 را نصب و دو دستور مربوط به nvm را رد کنید. `setup:local` فایل `apps/api/.env` را با رمزهای تصادفی PostgreSQL، Redis و JWT می‌سازد؛ اگر فایل موجود باشد آن را حفظ می‌کند. `infra:up` سرویس‌های محلی را راه‌اندازی و آماده شدن دیتابیس و Redis را بررسی می‌کند. نخستین نصب ممکن است به‌دلیل دریافت imageها طول بکشد.

نشانی‌های محلی:

وب‌سایت: [انگلیسی](http://localhost:3000/en) · [عربی](http://localhost:3000/ar). دستور `npm run dev` وب‌سایت و API را با هم اجرا می‌کند. برای اجرای جداگانه از `npm run dev:web` و `npm run dev:api` در دو ترمینال استفاده کنید.

اگر پورت پیش‌فرض API یعنی 4000 اشغال است، `API_PORT=4010 npm run dev` را اجرا کنید؛ راه‌انداز اتصال وب‌سایت را هم با همان پورت تنظیم می‌کند.

| سرویس                      | نشانی                                                  |
| -------------------------- | ------------------------------------------------------ |
| API                        | `http://localhost:4000/api/v1`                         |
| Swagger                    | [مستندات تعاملی](http://localhost:4000/api/docs)       |
| OpenAPI JSON               | [قرارداد API](http://localhost:4000/api/openapi.json)  |
| سلامت فرایند               | [Liveness](http://localhost:4000/api/v1/health/live)   |
| آمادگی دیتابیس و Redis     | [Readiness](http://localhost:4000/api/v1/health/ready) |
| ایمیل‌های آزمایشی          | [Mailpit](http://localhost:8025)                       |
| PostgreSQL از سیستم میزبان | `localhost:5433`                                       |
| Redis از سیستم میزبان      | `localhost:6380`                                       |

ایمیل‌های تأیید و بازیابی در Mailpit دیده می‌شوند. لینک آن‌ها به صفحات فرانت آینده می‌رود؛ تا زمان ساخت فرانت، مقدار `token` لینک را در Swagger به `POST /auth/email/verify` یا `POST /auth/password-reset/confirm` بدهید. ایمیل توسط outbox با فاصله چند ثانیه ارسال می‌شود.

برای ایجاد مدیر، مقادیر `ADMIN_EMAIL` و `ADMIN_PASSWORD` را در `apps/api/.env` وارد کنید، سپس اجرا کنید:

```bash
npm run admin:create
```

رمز مدیر باید ۱۶ تا ۱۲۸ کاراکتر، حداقل ۸ کاراکتر متمایز و فاقد کاراکتر کنترلی باشد؛ از رمز تصادفی یا عبارت عبور طولانی استفاده کنید. این حساب از ثبت‌نام عمومی ساخته نمی‌شود. اگر ایمیل از قبل حساب داشته باشد، CLI آن را تغییر نمی‌دهد. بعد از ساخت، مقدار `ADMIN_PASSWORD` را از فایل محیطی حذف کنید. ورود در ابزار HTTP به هدر `Origin: http://localhost:3000` نیاز دارد؛ نمونه‌ها در [راهنمای API](docs/api-guide.md) آمده‌اند.

بعد از نصب، فهرست‌ها خالی هستند؛ مدیر می‌تواند اطلاعات واقعی را از API بسازد. دستور seed فقط برای داده‌های نمایشی است، به فعال‌سازی صریح نیاز دارد و در production اجرا نمی‌شود:

```bash
SEED_DEMO=true npm run db:seed
```

این دستور در مجموع ۱۳ آگهی عمومی، ۴ پروژه، ۴ منطقه و ۴ پروفایل مشاور، همراه با متن EN/AR و ۹ تصویر نمایشی می‌سازد؛ داده‌های موجود را بازنویسی نمی‌کند. حساب مشاور demo رمز ورود منتشرشده ندارد. منابع و مجوز تصاویر در `apps/api/demo-assets` ثبت شده‌اند. این داده‌ها پیشنهاد واقعی فروش نیستند.

## نصب به‌صورت PWA

ORIVA با manifest استاندارد، آیکون‌های ۱۹۲ و ۵۱۲ پیکسلی، آیکون maskable و آیکون مخصوص Apple قابل نصب است. دکمهٔ **Install ORIVA** در پایین سایت، در مرورگرهای پشتیبان پنجرهٔ نصب و در مرورگرهای دیگر راهنمای نصب را باز می‌کند. در آیفون، سایت را در Safari باز کنید و از **Share → Add to Home Screen** استفاده کنید. نسخهٔ نصب‌شده در پنجرهٔ مستقل باز می‌شود؛ زبان انگلیسی پیش‌فرض است و تغییر زبان و تم درون برنامه در دسترس می‌ماند.

Service worker فقط در build تولید و روی HTTPS یا `localhost` فعال می‌شود؛ در حالت `next dev` ثبت نمی‌شود. برای بررسی محلی، پس از اجرای دیتابیس و Redis، در یک ترمینال `PORT=4010 npm start` و در ترمینال دیگری `npm run build:web` و سپس `BACKEND_INTERNAL_URL=http://127.0.0.1:4010 npm run start:web` را اجرا کنید. اگر سرور وب قبلاً روشن است، قبل از build آن را متوقف کنید. سایت در [لوکال](http://localhost:3000/en) نصب‌پذیر است؛ آدرس HTTP شبکهٔ داخلی روی موبایل جایگزین HTTPS نیست. راهنمای رسمی: [Next.js PWA](https://nextjs.org/docs/app/guides/progressive-web-apps).

هنگام قطع اینترنت، بارگذاری مستقیم صفحه، نمای آفلاین انگلیسی یا عربی را نشان می‌دهد و دکمهٔ تلاش مجدد همان نشانی را دوباره باز می‌کند. قیمت‌های زنده، فرم‌ها، پنل‌ها و پیام‌ها به اتصال نیاز دارند؛ ارسال آفلاین یا صف مخفی وجود ندارد. کش PWA فقط شامل صفحهٔ عمومی آفلاین و آیکون‌های مشخص است؛ پاسخ‌های API، صفحات HTML/RSC سایت، عکس‌های کاربران و اطلاعات احراز هویت در آن ذخیره نمی‌شوند. نسخهٔ جدید service worker، تا تأیید دکمهٔ **Update now** یا بسته‌شدن تب‌های نسخهٔ قبلی منتظر می‌ماند.

برای بازتولید آیکون‌ها پس از تغییر لوگوی SVG، `npm run icons:generate -w @real-estate/web` را اجرا کنید. هنگام تغییر فایل‌های نمای آفلاین یا آیکون‌ها، نسخهٔ کش در `apps/web/public/sw.js` را افزایش دهید. تست نصب‌پذیری مرورگر و رفتار آفلاین: `PLAYWRIGHT_BASE_URL=http://localhost:3000 npm run test:web -- pwa.spec.ts`.

## دستورهای روزمره

| دستور                                                          | کاربرد                                           |
| -------------------------------------------------------------- | ------------------------------------------------ |
| `npm run dev`                                                  | اجرای همزمان وب‌سایت و API با watch              |
| `npm run check`                                                | lint، typecheck، تست واحد و build                |
| `npm run test:e2e`                                             | تست یکپارچه با PostgreSQL، Redis و Mailpit واقعی |
| `npm run build` سپس `npm start`                                | build و اجرای خروجی کامپایل‌شده                  |
| `npm run db:migrate -w @real-estate/api -- --name your_change` | ساخت migration در توسعه                          |
| `npm run db:deploy`                                            | اعمال migrationهای موجود                         |
| `npm run openapi:export`                                       | خروجی گرفتن قرارداد API                          |
| `npm run infra:down`                                           | توقف سرویس‌های محلی با حفظ داده‌ها               |

تست e2e به کاربر PostgreSQL با مجوز `CREATEDB` نیاز دارد؛ کاربر محلی Compose آن را دارد. تست دیتابیس موقت خودش و پیشوند مستقل Redis می‌سازد؛ از دیتابیس عملیاتی برای اجرای تست استفاده نکنید.

## اجرای API داخل Docker

بعد از setup، راه‌اندازی زیرساخت و `db:deploy` بالا:

```bash
docker compose --env-file apps/api/.env --profile app up -d --build api
```

این حالت از تنظیمات توسعه و Mailpit استفاده می‌کند و API را روی پورت 4000 میزبان می‌آورد. اگر `npm run dev` روشن است، ابتدا آن را متوقف کنید. داده‌های PostgreSQL، Redis و تصاویر در volume باقی می‌مانند. دیتابیس در startup برنامه migration نمی‌شود.

برای ساخت image تولید:

```bash
docker build --target runtime -t uae-real-estate-api:local .
```

image نهایی با کاربر غیر root اجرا می‌شود و dev dependencyها را ندارد. تنظیمات production، migration جداگانه، نگهداری تصاویر و محدودیت‌های استقرار در [معماری](docs/architecture.md) و [امنیت](SECURITY.md) توضیح داده شده‌اند.

## مستندات

برای build از `npm run build:api` و `npm run build:web` استفاده کنید؛ سپس API را با `npm start` و وب‌سایت را با `npm run start:web` در دو ترمینال اجرا کنید. `npm run test:web` مسیرهای واقعی مرورگر، هندسهٔ پرچم و سیاست درگاه تیم را بررسی می‌کند؛ Chrome محلی یا Chromium نصب‌شدهٔ Playwright لازم است. تست‌های حساب‌های شخصی به فایل خصوصی معرفی‌شده در [راهنمای پنل تیم](docs/team-workspace.md) نیاز دارند. راهنمای [استقرار در Vercel و Replit و اتصال Render](docs/deployment.md) محدودیت‌های میزبانی نمایشی را توضیح می‌دهد.
